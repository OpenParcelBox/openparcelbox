# OpenParcelBox Governance

OpenParcelBox is initiated and maintained by Jan Elsner / OpenParcelBox Project.

The project welcomes community contributions while maintaining clear responsibility for security, architecture, official releases, brand use and long-term direction.

## Project goals

OpenParcelBox aims to provide an open, local-first and self-hostable foundation for:

- smart parcel boxes
- retrofit parcel locks
- secure bridge firmware
- MQTT and Home Assistant integration
- optional cloud services
- plugin systems
- public locker infrastructure
- commercial integrations
- enterprise locker systems

## Maintainer authority

Maintainers are responsible for:

- accepting or rejecting contributions
- defining project roadmap
- maintaining security architecture
- approving releases
- managing official repositories
- defining compatibility rules
- enforcing contribution requirements
- enforcing trademark and brand policy
- protecting local-first and self-hosting principles

## Community contributions

Community contributions are welcome through issues, discussions, pull requests, documentation, testing, design proposals and integration work.

All contributions must follow the contribution rules in `CONTRIBUTING.md`, including DCO sign-off.

## Technical decisions

Important technical decisions should be documented transparently where practical, for example in:

- GitHub issues
- GitHub discussions
- pull requests
- architecture decision records
- roadmap documents
- specification documents

## Commercial partners

Commercial partners, customers or sponsors do not automatically receive control over the OpenParcelBox community project, roadmap, security model, brand or official releases.

Commercial cooperation may influence priorities, but project maintainers retain final authority over community project decisions.

Commissioned or sponsored project work should normally be developed in the open and contributed back to the public project where legally and contractually possible.

OpenParcelBox may later sell finished devices, retrofit kits, cloud services, consulting, integration work, support or certification. Commercial activity should remain compatible with the project goal that the community can inspect, rebuild and improve the open designs under their licenses.

## Priority principles

The following principles have priority in project decisions:

- local-first operation
- self-hosting support
- open and auditable core
- no artificial cloud lock-in
- security-sensitive decisions handled by the Core
- meaningful community benefit
- clear brand separation
- responsible commercial development

## Future governance

The project may later introduce additional governance roles, such as:

- maintainers
- security team
- documentation maintainers
- plugin reviewers
- hardware reviewers
- advisory board
- certification reviewers
- foundation, cooperative, association, company or similar operating structure

Any future governance structure should preserve the project’s local-first, self-hostable and community-benefit principles.

The OpenParcelBox name, logo, domain identity and related marks remain protected project identifiers controlled by the project founder/maintainer unless a future written agreement explicitly changes that.
